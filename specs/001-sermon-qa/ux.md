- **對應**：[spec.md](./spec.md)、[plan.md](./plan.md)
- **狀態**：草稿（待確認）
- 畫面編號：`M` = 會友端、`A` = 管理端。線框圖只表達資訊與版面，不代表最終視覺。

## 1. 核心決策：會友與管理者如何區分

### 1.1 比較過的三種做法

| 做法                              | 說明                                                                               | 優點                               | 缺點                                                                                              |
| --------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------- |
| A. 同一頁，多幾個按鈕             | 管理者登入後，會友留言板上多出「回覆、隱藏」                                       | 開發最少                           | 隱藏的留言要不要顯示？篩選「待回應」放哪？場次開關、QR 放哪？全部擠在一頁；手機上容易誤觸「隱藏」 |
| B. 兩套完全獨立的介面             | 會友端、管理端各自設計                                                             | 各自最佳化                         | 卡片樣式不一致，牧者看不到「會友實際看到的樣子」；重複開發                                        |
| **C. 兩個入口＋共用元件（採用）** | 會友端與管理端是不同頁面、不同版型，但**留言卡片是同一個元件**，管理模式多一列操作 | 任務分流清楚，視覺一致，開發量適中 | 需要把卡片元件設計成可切換模式                                                                    |

### 1.2 為什麼採用 C

兩種角色**要完成的事不同**，不只是權限不同：

|          | 會友               | 管理者（牧者、同工）                         |
| -------- | ------------------ | -------------------------------------------- |
| 主要目的 | 參與：看、問、附議 | 分流處理：找出值得回應的、回應、清除不當內容 |
| 使用時機 | 聚會中，坐在座位上 | 聚會中（台下/講台旁）與會後                  |
| 主要裝置 | 手機，單手         | 聚會中用手機或平板，會後用電腦               |
| 需要看到 | 公開留言、牧者回覆 | 全部留言（含隱藏）、待回應數量、場次狀態     |
| 主要動作 | 發留言、附議       | 篩選、回覆、隱藏、開關場次、顯示 QR          |

### 1.3 具體規則

1. **網址分開**：會友 `/s/:code`，管理端 `/admin/...`。QR code 永遠只指向會友網址。
2. **版型分開**：
   - 會友端 `MemberLayout`：沒有選單，只有場次資訊和留言，越少干擾越好。
   - **「放大」只在頁首**（兩端都一樣，spec D13）：從目前篩選與排序的第一則開始，進入後用上一則／下一則、鍵盤或滾輪切換。
   - **篩選列兩端共用**（`FilterTabs`）：`全部 N ｜ 待回應 N ｜ 已回應 N`，管理端再多 `已隱藏 N`；右側是排序（最新／最舊／最多附議／最新回應，按鈕上簡寫為「最新／最舊／附議／新回應」）。「全部」放第一個且為預設。
   - 會友端頁首 `MemberHeader`（2026-11-03 加入）：白底、固定在頂端、底部細線、高 56px，內容寬度與頁面相同（最大 720px）。
     - 左：「世界之光聖教會 | ECHO」（不放標誌）（2026-11-22，字型、字級 16px、粗體、字距 0.1em 與報名系統 tnlhc-signup 頁首相同）；留言板前面多「‹」，整組點了回首頁（場次列表）。
     - 右：頁面動作，留言板是「QR code」「放大」，**只在平板、電腦顯示**（手機沒有，spec D16）。「QR code」開全螢幕 QR（與 A6 的全螢幕投影相同，不需登入；spec AC5.12）。
     - 留言板往下捲到看不到場次標題時，教會名稱換成場次標題（單行、過長省略）。
     - **沒有**頂端細條，跟管理端區分（第 3 點）。
   - 管理端 `AdminLayout`：頂部有工具列和帳號選單，電腦上有側欄，看起來就是「後台」。
   - 管理端頁首固定在頂端（2026-11-05）：頂端細條＋「ECHO 管理」頂部列在各寬度都固定；場次頁的標題列（標題、狀態、設定結束時間、放大、分享 QR、編輯場次資訊）在 ≥1024px 也固定，手機上太高，跟會友端的場次資訊一樣捲走。
3. **顏色辨識**：兩端都是白底、白卡片（§7）。管理端頂端多一條 3px 深抹茶細條和「ECHO 管理」字樣，牧者同時開兩個分頁也不會搞混。
4. **共用留言卡片**：`PostCard` 有 `mode="member" | "admin"`：
   - 內容、暱稱、附議數、回覆的呈現**完全相同**，牧者看到的就是會友看到的。
   - `admin` 模式多一列操作：`回覆`、`隱藏`、`刪除`（spec D15）。被隱藏的卡片會變淡並標示「已隱藏」。
   - `admin` 模式下，卡片上的每則回覆右上角有 `刪除`，可以單獨刪除回覆、保留留言（spec AC7.5）。
   - `member` 模式只有：`附議`。會友不能刪除留言（spec AC2.4），也沒有「我的留言」標示（spec D11）。
5. **管理者打開會友網址時**：看到的是一般會友畫面（方便確認會友看到什麼），頂部多一條提示列：「你目前以管理者身分登入 · 前往管理此場次 →」。會友端**不會**出現任何管理按鈕。
6. **從管理端到會友畫面**：場次管理頁「⋯」選單的「前往會友留言板」，在同一個分頁打開會友網址；會友頁頂端的提示列可以回到管理頁（spec AC5.8、D16）。

## 2.1 響應式設計（RWD）

會友端與管理端都必須在**手機、平板、筆電／桌機**上完整可用（AC1.6、AC5.10）。設計稿每一列由左到右即為手機 → 大螢幕。

**斷點**（沿用 Quasar 預設，另加一個 1280）：

| 代號 | 寬度        | 典型裝置           |
| ---- | ----------- | ------------------ |
| xs   | < 600px     | 手機直拿           |
| sm   | 600–1023px  | 平板直拿、手機橫拿 |
| md   | 1024–1279px | 平板橫放、小筆電   |
| lg+  | ≥ 1280px    | 筆電、桌機         |

**會友端**

| 畫面             | xs 手機                                                     | sm 平板                             | md / lg 筆電、桌機                                                     |
| ---------------- | ----------------------------------------------------------- | ----------------------------------- | ---------------------------------------------------------------------- |
| M1 首頁          | 單欄滿版                                                    | 內容置中，最大寬 720px              | 同 sm                                                                  |
| M2 留言板        | 單欄滿版，底部固定輸入列 → 點開對話框 M3（靠上）            | 置中 720px，底部輸入列 → 置中對話框 | 置中 720px，頂部頂端導覽列；**撰寫框直接展開在列表上方**，不需另開面板 |
| 過去場次（唯讀） | 同 M2，底部改為「本場次已結束」灰色列；頁首一樣有「‹ ECHO」 | 同左                                | 同 M2 電腦版，無撰寫框                                                 |

**管理端**

| 畫面        | xs 手機                                                                                                  | sm 平板          | md 平板橫放                           | lg+ 筆電                                                |
| ----------- | -------------------------------------------------------------------------------------------------------- | ---------------- | ------------------------------------- | ------------------------------------------------------- |
| A2 場次列表 | 獨立頁，兩行列表                                                                                         | 獨立頁           | 獨立頁                                | **固定在左側欄（272px）**，進行中／過去的場次可直接切換 |
| A4 場次管理 | 標題列＋「⋯」選單；「分享 QR」「編輯場次資訊」按鈕放在標題下；分頁可左右滑；每則留言的操作列放在內容下方 | 單欄，操作放右側 | 左右兩欄：列表＋右側回覆面板（340px） | 側欄＋列表＋回覆面板（380px）                           |
| A5 回覆     | 全螢幕對話框                                                                                             | 置中對話框       | 右側面板                              | 右側面板                                                |
| A7 講台小卡 | 卡片寬度滿版、高度隨內容（至少 260px），問題 24px；提示「橫放手機可以看得更大」；手機橫放時改回 16:10    | 16:10，問題 30px | 16:10，問題 34px                      | 16:10（960×600），問題 42px                             |

**共通規則**

- 觸控區一律 ≥ 44px（講台模式 ≥ 56px），不因螢幕變大而縮小。
- 不做「只有電腦版才有」的功能，手機上一定找得到（可能收在「⋯」選單裡）。
- 文字行寬最多約 40 個中文字（720px），大螢幕不無限拉寬。
- 驗收寬度：360、390、768、1024、1366、1440、1920（T054）。

├───────────────────────────

- 頁尾**沒有**「管理者登入」連結（spec D14）：會友端不出現任何後台入口。
- **不放副標語**（2026-11-16）：同一套系統會用在講道、活動等不同場合，首頁與頁首只用通用文字。場次表單也用通用欄位名稱：標題、日期、講員／主講人、經文／副標題。

- 輸入滿 6 碼自動送出；場次碼錯誤時欄位下方顯示「找不到此場次，請確認場次碼」。
- 「進行中」只在有開放中的場次時出現；「過去的場次」每次載入 20 筆（AC8.4）。

├───────────────────────────   ← 細線分隔，不做浮起的卡片

│ [↑ 3]
├───────────────────────────

├───────────────────────────

└───────────────────────────
```

- 留言之間用細線分隔，不做一張張浮起的卡片。
- 不區分問題或心得（spec B-10），每則只顯示暱稱與時間。
- 牧者回覆放在淺灰底區塊中，超過 3 行時收合並顯示「展開全文」。
- 底部固定一條像聊天輸入框的按鈕，比浮動按鈕更容易理解，點了打開 M3。
- 標題區往下捲動時收合成單行（只剩標題）。
- 選擇的排序與篩選記在 `sessionStorage`。

### M3 撰寫留言（撰寫面板）

```
┌───────────────────────────
│ 取消       撰寫留言     [送出]   ← 送出放頂列，鍵盤彈出也看得到
├───────────────────────────
│ 寫下你的問題、感動或回應…
│                                ← 輸入框佔滿剩下的空間
│
├───────────────────────────
│ 暱稱（選填，不填顯示匿名） 0/500 ← 單行，貼在鍵盤正上方
└─────────────────────────── ← 鍵盤上緣
```

- **撰寫面板**（`ComposeSheet`，2026-11-16）：會友撰寫留言與管理者回覆（A5）**共用同一個外觀與行為**。
  - **手機**：全螢幕，高度永遠等於鍵盤以外的可視範圍（`visualViewport`），並跟著 iOS 的捲動位移；鍵盤收起時底部保留安全區域。
  - **平板**（以及講台模式的回覆）：同樣的版面做成置中卡片，高度同樣不超過鍵盤以外的可視範圍。
  - 電腦不開面板，撰寫框直接展開在列表上方（M2）。
  - 原因：iPhone 鍵盤佔掉一半以上的高度，原本的對話框（標題、5 行輸入框、暱稱欄＋說明、大「送出」按鈕）塞不下，輸入框被擠扁、版面破掉。
  - 不用底部面板：iOS Safari 鍵盤彈出時不會縮小版面，貼在底部的面板會被鍵盤蓋住或跟著亂跳（2026-11-05）。
- 底部固定的「寫下你的問題或回應…」只是按鈕，不是輸入框，點了才開對話框，所以不受鍵盤影響。
- 送出後對話框關閉，馬上在列表最上方看到自己的留言；排序是「最舊」時，留言放在最下方並自動捲過去。
- 送出時按鈕顯示 loading；成功後顯示 snackbar「已送出」。
- 失敗時面板保持開啟、內容保留，顯示錯誤（例如「留言太頻繁，請稍後再試」）。
- 尚未送出的草稿暫存在 `sessionStorage`，不小心關閉面板也不會遺失。

## 4. 管理端畫面

### A1 登入

- 只有「管理密碼」欄位與登入按鈕（spec D14）；密碼錯誤顯示「密碼錯誤」。
- 只能直接輸入網址 `/admin` 進入，會友端沒有連結。
- 不提供註冊；「忘記密碼請聯絡系統管理者」。
- 共用管理帳號還沒加入管理名單 → 「管理帳號尚未設定完成，請聯絡系統管理者」。

### A2 場次列表

```
┌─ 管理工具列 ─────────────────────────────
│ ECHO 管理        [+ 新增場次]      王牧師 ▾
├──────────────────────────────────────────
│ 篩選：(全部) (開放中) (草稿) (已結束)   🔍 搜尋標題
├──────────────────────────────────────────
│ ● 開放中  11/8  恩典的記號      留言 24 · 待回應 6   ›
│ ○ 草稿    11/15 （未命名）       —                   ›
│ ■ 已結束  11/1  信心的功課      留言 31 · 待回應 0   ›
└──────────────────────────────────────────
```

- 「開放中」的場次永遠置頂。
- 「待回應」= 未隱藏、沒有文字回覆的留言數；大於 0 時以粗體標示。
- 有設定自動結束的開放中場次，顯示「12:30 自動結束」。
- 手機上每列改成兩行卡片。

### A3 建立 / 編輯場次

設計稿「建立新場次流程」畫板可以從頭點到尾。整個流程三步：

```
① 場次列表 ──[＋ 新增場次]──▶ ② 表單 ──[建立並開放留言]──▶ ③ 場次頁：QR + 全螢幕投影
                                       └─[先存成草稿]────▶ ③' 場次頁：草稿 + [開放留言]
```

**② 表單**

| 欄位         | 必填 | 預設值                                                       |
| ------------ | ---- | ------------------------------------------------------------ |
| 講道標題     | ✓    | —                                                            |
| 日期         | ✓    | 下一個主日（今天是主日就是今天）                             |
| 講員         |      | 上一場的講員；輸入時提示過去用過的講員名稱                   |
| 經文         |      | —                                                            |
| 設定留言結束時間（2026-11-22 由「自動結束時間」改名） |      | 空白。日期＋時間（15 分鐘為單位）；先選時間，日期預設為講道日期，可改成其他天；可清除；不能選已過的時間 |

- 手機：全螢幕頁面，兩顆按鈕固定在底部。平板、筆電：右側滑出面板（寬 480px），列表仍在背後看得到。
- 送出按鈕：**建立並開放留言**（主要）。~~**先存成草稿**（次要）~~ 目前隱藏（spec D17，2026-11-16）。主日早上臨時建立的牧者按一下就能開始。
- 建立後直接進入 ③ 場次頁，最上方是 QR code、場次碼、「全螢幕投影 QR」「複製連結」，下面才是留言列表。
- 草稿狀態的 ③' 頁面會提醒「會友現在掃碼會看到『找不到此場次』」，並放一顆「開放留言」按鈕。

**編輯**：A4 標題列的「編輯場次資訊」按鈕（2026-11-22 從「⋯」選單移出），使用同一張表單，送出按鈕改為「儲存」。A4 頂部狀態旁也可以直接點「設定結束時間」按鈕（外框按鈕，已設定時顯示「修改結束時間」）快速修改：小對話框，同樣是日期＋時間（日期預設為講道日期，已經過了就用今天）。對話框左下角有「立即結束留言」（紅字，需確認），右下角是「取消」「儲存」。

### A5 回覆編輯器

- **手機、平板、講台模式**：與會友撰寫留言相同的撰寫面板（M3，2026-11-16）：

  ```
  ┌───────────────────────────
  │ 取消       回覆留言     [送出]
  ├───────────────────────────
  │ 匿名 · 10:32 · ↑ 5               ← 原留言與已有回覆，可捲動
  │ 請問牧師提到的…                     （最多佔面板高度的 40%）
  │ ┌ 牧者 · 10:40 ─────────────
  │ │ 謝謝提問…        編輯  刪除
  ├───────────────────────────
  │ 回覆會顯示在這則留言下方…        ← 輸入框佔滿剩下的空間
  ├───────────────────────────
  │ 回應者 [未填寫預設為「牧者」]  0/2000   ← placeholder，留空即為「牧者」（spec AC6.2、D18）
  └───────────────────────────
  ```

  - 按已有回覆的「編輯」：內容載入同一個輸入框，頂列變成「編輯回覆 · 儲存」，回覆旁顯示「編輯中 · 取消編輯」。只有一個輸入框，不會在小螢幕上同時出現兩個。
  - 尚未送出的回覆草稿暫存在 `sessionStorage`（每則留言各自一份），編輯完舊回覆會回到草稿。
- **電腦（≥1024px）的場次管理頁**：右側回覆面板（不是彈出式，沒有鍵盤問題）。
- 上方固定顯示原留言，避免回覆時看不到題目。
- 已有的回覆列在原留言下方，自己的回覆可以編輯、刪除。
- 回應者名稱欄位放在輸入框下方（手機為面板底列，電腦為輸入框下方獨立一列），輸入框預設空白、placeholder 為「未填寫預設為「牧者」」（看得出可以輸入），留空送出即顯示「牧者」；同一個分頁內記住上次填的名稱（`sessionStorage`）。編輯舊回覆時不顯示此欄位，名稱不變。
- 送出後關閉面板（電腦版清空輸入框），回覆立即顯示在留言卡片下方，並在「待回應」篩選中移除（留言列表不另外標示「已回應」，spec D19）。
- 快捷鍵：`Ctrl + Enter` 送出。

### A7 講台模式（小卡）

在 A4 按頁首的「放大」，同一台裝置進入全螢幕，留言放大成一張像實體小卡的卡片（設計稿「平板場次管理」畫板可直接點點看）。

**會友端也能放大**（AC9.6）：投影的同工不一定有管理帳號。會友端在平板、電腦的頁首有「放大」（從目前篩選與排序的第一則開始；手機沒有，spec D16）。小卡外觀完全相同，只是沒有「文字回覆」，也只看得到公開留言。網址 `/s/:code/stage?post=<id>` 可以直接傳給投影同工。

```
┌──────────────────────────────────────────────────────  淺灰背景 #EFEFEA
│ 講台模式 · 待回應 · 依附議排序                    關閉
│
│        恩典的記號 · 11/8                          ← 場次名稱在卡片外左上方
│        ┌─────────────────────────────────────┐   白色小卡，圓角 6px
│        │ Q.03                                │   唯一有陰影的元件
│        │                                     │
│        │ 「稱義」和「成聖」的差別是什麼？     │   34px / 500
│        │ 兩者是同時發生的嗎？                 │
│        │                                     │
│        │ ─────────────────────────────────── │
│        │ 小明                             ↑ 12 │   ← 留言者暱稱（未填顯示匿名）

│
│          ← 上一則    3 / 6    下一則 →  │ [文字回覆]
└──────────────────────────────────────────────────────

- **小卡風格**：白色卡片放在淺灰背景上，有編號（Q.03）、細分隔線和頁尾資訊，像一張可以拿在手上的卡片。
- **比例**：橫式 16:10（已定案）。手機直拿時例外，見 §2.1。
- **場次名稱**：放在卡片外左上方（場次標題＋日期），卡片內不再重複（2026-11-22）。
- **頁尾**：左邊是留言者暱稱（未填顯示「匿名」，spec D2，2026-11-22 改），右邊是附議數。原本的「會友留言」與「已回應」都拿掉。
- **順序**：沿用進入時的篩選與排序（例如「待回應＋最多附議」），所以牧者可以從最熱門的問題依序講下去。
- **操作**：按鈕觸控區 ≥ 56px（站著用平板時比較好按）；鍵盤 `←` `→` 切換、`Esc` 離開；滑鼠滾輪或觸控板上下捲動也能切換（往下＝下一則，一次捲動只換一則，不會因觸控板慣性連跳好幾則）。
- **全螢幕**：進入時呼叫瀏覽器 Fullscreen API；不支援全螢幕的裝置（iPhone Safari）就以整頁顯示。
- **文字回覆**：開啟 A5 回覆編輯器（手機、平板是對話框），送出後回到小卡。
- **即時更新**：附議數即時變動；目前這則被隱藏時，自動切到下一則並提示「此留言已被隱藏」。
- **網址**：使用 `?post=<id>`，重新整理或按瀏覽器上一頁都能回到正確狀態。

## 6. 互動細節

1. **新留言即時進來時不讓畫面跳動**：
   - 使用者在列表頂端 → 新留言直接淡入。
   - 使用者已往下捲 → 不插入，頂部顯示「↑ 3 則新留言」文字按鈕，點擊後捲回頂端並插入。
   - 排序是「最舊」時，新留言加在列表最下方，不會推動畫面，所以直接插入、不顯示提示（2026-11-16）。
2. **「最多附議」「最新回應」排序下不即時重排**：附議數、回覆會即時更新，但卡片不會在眼前跳位置；顯示「排序已變動，點此更新」。
3. **附議**：按下立即 +1（樂觀更新），失敗時還原並提示。按鈕觸控區 ≥ 44px。
4. **隱藏留言（管理端）**：不跳確認，改用 snackbar「已隱藏 · 復原」（5 秒內可復原）。比較快，誤按也救得回來。
   **刪除留言（管理端，spec D15、D20）**：刪除＝封存，App 內看不到但資料保留。仍一定跳確認對話框「刪除這則留言？刪除後，會友與管理端都看不到這則留言和它的回覆；資料仍會保留，需要時可請系統管理者還原。」（紅色「刪除」）。刪除後所有畫面即時移除。場次與回覆的刪除也一樣是封存。
   **刪除回覆**：同樣先確認「刪除這則回覆？」。可在後台留言卡片上直接刪（AC7.5），也可在回覆面板（A5）刪。
5. **刪除場次**：需輸入場次標題才能確認。
6. **時間顯示**：1 小時內用相對時間（3 分鐘前），之後用 `HH:mm`，跨日用 `M/D HH:mm`。

## 7. 視覺規範（白底＋深抹茶強調色，2026-11-16 改）

強調色取自 Astryx「Matcha」（<https://astryx.atmeta.com/themes?theme=matcha>，只取淺色）；整頁米色／綠色版試過後太重，改回白底。

**原則：白底、白卡片、近黑文字，深抹茶只當強調色。**

1. 頁面與卡片都是白色；卡片靠 1px 淺灰框和圓角分隔（留言卡片、場次列表、提示框）。
2. 文字是中性的近黑與灰，**不用綠色文字**。
3. 深抹茶（`#3E481D`）只用在：主要按鈕、選中狀態、「已附議」（實心）、新留言提示、管理端頂端細條、focus 外框。
4. 亮綠只表示「狀態好」：「已回應」、開放中的圓點。紅色只用於錯誤與刪除。
5. 卡片列表和上方「全部／待回應」那排之間留 12px 空隙；卡片之間 8px。
6. 不用漸層、表情符號、插圖。陰影只用在講台小卡與浮動的「↑ N 則新留言」。
7. **只有淺色，不做深色模式**：`color-scheme: light`，瀏覽器不會自動套深色。

| ----------- | ---------------------------------------------------------------------------------------------------------------------- |
